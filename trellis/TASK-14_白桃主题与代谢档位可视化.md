## 一、背景与目标

### 1. 来源与痛点
1. **代谢需求读不出状态**（见 `_外部审阅_代谢需求档位可视化.md`）：
   - 尿意、便意等需求的上限（urge/hard）是弹性的，屏幕上孤零零的裸数字（如 `48`）无法体现角色是“尚早”还是“快憋不住了”。
   - 三层图标的溢出层存在严重撞色 Bug：`value >= urge` 时，`tile--high` 将填充层与溢出层覆写为完全相同的红色，导致“满”和“爆”肉眼无法区分。
   - **设计定位**：不贴生硬的内部评级汉字（拒绝“中/满/爆”等机械打补丁标签），保持 80×87 格子的纯净度，改为**纯视觉状态机**。
2. **拟物做旧导致视觉疲劳**：
   - 原版 BB 机（`theme-retro` 等）使用了 90 年代细等宽字体 `Courier New`，小字号下字形发虚。
   - 屏幕上覆盖了 `100% 3px` 的 CRT 栅格扫描线，边缘有 `inset 0 0 40px` 的深黑阴影，整体观感浑浊、对比度低、长时间查看容易眼疲劳。

### 2. 目标
1. **落地一套高清晰、高对比度、带二次元微黄油温润调性的新主题【白桃水光】（`theme-peach`）**。
   - 彻底消灭发虚、发灰、暗角遮挡的毛病，保证字迹锐利、阅读极度舒服。
   - 配色采用温润粉白底 + 深酒红黑字，过线时呈草莓红警示，保持干净清爽的同时具有适度色气感。
   - 完整适配主窗口面板与最小化悬浮球（`floating-sphere`）。
   - 顺带修复现有代码中 `applyTheme` 遗漏的主题选项按钮 `.is-active` 激活态高亮回显。
2. **落地代谢需求的“纯视觉状态机”（跨主题通用）**。
   - 格子不写中文档名，仅靠图标充盈度、双色溢出层与极限呼吸光来区分生理状态。
   - 严密兼容 `stool`（便意段号 0~5）、衍生种族 `flux`（双极性）以及代谢免疫态（`immune.metabolism`）。
3. **维护多角色独立性**。
   - 状态指示精准收敛在各自角色的属性格子里，不做粗暴的全局不可逆改色，保证角色界限清晰。

## 三、代谢需求：纯视觉状态机规范（跨主题通用）

不写任何生硬的中文档名（不贴“中/满/爆”），保持格子的简洁与纯粹。通过数据层现成的 `value`、`urge`、`cap`、`level`，在格子上派生出 4 种清晰的**生理状态类（State Class）**：

```
[平静态 Calm]   -->   [充盈态 Filled]   -->   [憋耐态 Urgent]   -->   [极限态 Critical]
  未满格              100% 满格线             溢出层双色蔓延          边框心跳呼吸脉冲
  默认半透底色        图标转粉红              数字微红                濒临失控报警
```

### 1. 跨需求状态映射引擎

针对不同需求的底层数据结构，建立精确的状态映射（函数：`getMetabolismNeedState(item)`）：

| 需求项 | 数据特征 | 平静态（Calm） | 充盈态（Filled） | 憋耐态（Urgent） | 极限态（Critical） |
|---|---|---|---|---|---|
| **常规项**<br>（尿意/饿意/困意/乳意） | `level` 字符串<br>（无/低/中/高/满/爆） | `level` 为无/低/中 | `value >= urge` 或 `level` 为高/满（且无溢出） | `overfill > 0` 且 `level` 未达爆 | `level === '爆'` |
| **便意项**<br>（`stool`） | `level` 为段号数字<br>（`0 ~ 5`） | `level` 为 0 或 1 | `level` 为 2 或 3（已过 urge 推力段） | `level === 4`（达到 discomfort 阈值） | `level === 5`（达到 pain 疼痛阻力段） |
| **衍生项**<br>（`flux`） | 双向浮动值<br>（-cap ~ +cap） | 保持原有正负极平衡态，**不参与单向溢出状态机**，沿用 `--positive`/`--negative` | — | — | 当 `abs(value) >= 125 * scale`（爆发态）时可选加上呼吸红光 |

### 2. 双层液面替换机制（解决撞色 Bug 的核心原理）
- **代码结构依据**：
  在 `style.css` 中，`.bs-bt-need-icon-fill` 与 `.bs-bt-need-icon-overfill` 均以 `inset: auto 0 0 0` 从底部向上生长，内嵌图标高度均为 34px。
- **物理呈现过程**：
  1. **蓄满阶段（0 → urge）**：第 2 层（fill）从 0% 涨到 100%，整颗图标呈现温和粉红（`--bs-bt-need-filled-color`）。
  2. **溢出憋耐阶段（urge → cap）**：第 3 层（overfill）以深浓血红（`--bs-bt-need-over-color`）从底部往上漫延，**自底向上逐步覆盖替换掉粉红色**。
  3. **视觉感知**：玩家可以清晰肉眼观察到底部深红液面占整颗图标的比例，直观知晓角色忍耐余量剩余多少。

### 3. 四阶视觉呈现与样式规约

| 状态类名 | 视觉表现与样式规约 |
|---|---|
| `.bs-bt-need-tile--state-calm` | • 格子保持常规半透底色与淡灰细边框。<br>• 数值显示为正常主文字色。<br>• 图标填充层按比例自然上升，底纹安静。 |

## 附录 A：修订建议——黄油化语义与三层可读性架构（2026-09-04 外部审阅补充）

> 本附录不改变 TASK-14 的核心机制（双层液面、四阶状态类、flux 保护、无障碍降级全部保留），只修订**色彩语义、动效分层与装饰边界**。核心原则一句话：**黄油感交给光、色、图标、边框去演；文字只做一件事——稳稳地躺在那里让人看清。**

### A.1 三层分离架构（最高优先级约束）

整个主题按"能不能动、对比度多少"切成三层，各层有硬性规矩：

```
第 1 层 · 文字层（数字、标签）        → 永远静止，永远高对比，任何状态不变形不抖动
第 2 层 · 状态层（图标液面、边框、光晕）→ 随便动：液面涨落、边框呼吸、图标微颤都可以
第 3 层 · 装饰层（高光、蕾丝、爱心）    → 静态或极缓，绝不压在文字上
```

设计意图：玩家用**余光**感知状态变化（第 2 层），用**眼睛**读数字（第 1 层），两条通道互不干扰。

#### 文字层三条铁律

1. **数字和标签不参与任何动画**。所有 `animation` / `transition` 的选择器中禁止出现 `.bs-bt-need-value` 与 `.bs-bt-need-label`。
2. **数字变色只许在两个深色之间切换**（浅色是装饰色，不是文字色）：
   - 常态：`#4a1f2e`（深玫瑰棕，对 `#fff5f0` 底对比度约 12:1，远超 WCAG AAA 的 7:1）
   - Urgent / Critical：`#c22e4f`（深樱红，对比度约 5.5:1；数字为 0.82em 粗体，实际可读性充足）
   - **禁止**使用 `#f472b6` 等浅粉作为文字色。
3. **字号、字重、位置在任何状态下不变**。状态切换只换 `color`，不碰 `font-size` / `font-weight` / `transform`，避免重排与跳动感。

#### 状态层动效规约

- **液面涨落**：发生在图标上，是图形不是文字，可自由表现。
- **Critical 心跳**：只动 `box-shadow` 光晕（复用产痛 `bs-bt-labor-critical-pulse`），格子本身与格子内的字纹丝不动。
- **"她在喘"的表现**：不做格子整体浮动（会带动文字），改为**仅图标轻轻缩放**（`transform: scale(1 → 1.06)`，1.5s 与心跳同频）。图标是 34×34 图形，动起来是"胸口的起伏"，文字完全不受影响。
- **满档确认反馈**：图标在满格瞬间做一次轻微弹跳（`scale 1 → 1.15 → 1`，0.3s，仅触发一次不循环），像"满了"的确认感。

#### 装饰层边界

- **高光**：只放在外壳与屏幕最顶部 15% 区域（标题栏，无数据），透明度 ≤ 0.35，`z-index` 压在文字层之下。**格子内部不放高光**——格子太小，高光必糊字。
- **蕾丝/波浪边**：只做在屏幕顶部标题栏下边缘，1~2px 高，远离数据区。
- **爱心**：Critical 时出现在格子**右上角**，8px 大小（`::after` + `content: '♥'`，Unicode 字符，不违反"不新增图标资源"约束）。格子内图标与数字都在中轴线上，物理不重叠。
- **悬浮球搏动**：球上无文字，可自由搏动，是最安全也最有味道的动效位。

### A.2 色彩语义修订：从"报警"到"动情"

核心洞察：日系黄油 UI 的状态色不是"警告色"而是"动情色"。同样是红，一个是医院监护仪的红，一个是腮红的红。"满了"不是"超标了"，是"攒满了"——同一液面上涨，前者让人期待，后者让人紧张。

#### 底色：从"粉白"改成"肤色"

| 变量 | 原方案 | 修订值 | 说明 |
|---|---|---|---|
| `--bsbt-lcd-bg` | `#fff7f9` | `#fff5f0` | 带一点橘调的蜜桃奶白。纯粉白是"少女系"，偏橘的蜜桃白才是"肌肤系"。亮度几乎不变，对比度不受影响 |
| `--bsbt-lcd-text` | `#3a1426` | `#4a1f2e` | 暖一点的深玫瑰棕 |
| `--bsbt-pager-bg` | `#fff0f5→#ffd1dc` | `linear-gradient(160deg, #ffeef2 0%, #ffd6e0 55%, #ffc9d9 100%)` | 更暖的外壳渐变 |

#### 状态色：四阶"动情"语义

| 阶段 | 原方案（报警语义） | 修订（黄油语义） |
|---|---|---|
| 未满 | 文字色液面 | 淡粉液面 `#f9c5d5`，安静 |
| 满格 | 温和粉红 `#f472b6` | 桃花粉 `#f78fb0` + 格子边框泛微光，像"开始脸红" |
| 过线 | 深血红 `#9f1239` | 蜜桃红 `#e85d7a` 液面上涌（`#9f1239` 是血，`#e85d7a` 是吻痕） |
| 极限 | 警示红 + 心跳脉冲 | 深樱红 `#c93a5e` + 心跳光晕 + 图标轻缩放 + 右上角小爱心 |

跨主题回退色同步调整：overfill 的 `#b91c1c` 建议调为 `#d64560`，避免在其他主题下也呈现"血色报警感"。

### A.3 补充优化项

1. **数字等宽（强烈建议）**：`font-variant-numeric: tabular-nums;` 应用于 `.bs-bt-need-value` 与屏幕数字区。Chiron GoRound TC 支持等宽数字特性，消除数值跳动时的左右抖动，是"阅读极度舒服"目标里性价比最高的一条。
2. **Calm 态颜色连续插值（可选增强）**：现方案中 Calm 态 fill 颜色不随进度变化，"离过线还有多远"的信息在过线前是缺失的。可用 `color-mix` 按充盈比例插值（文字色 → 淡粉），让颜色从"阶跃"变成"渐变 + 阈值标记"。JS 侧仅需多输出一个 CSS 变量，不动数据层。
3. **交互态补全**：配色表需补充 hover / active / focus-visible（建议玫瑰金 `#c98a9d` 2px 焦点框）、`::selection`（建议 `rgba(244, 114, 182, 0.3)`）、屏幕区细粉滚动条、`color-scheme: light`（防系统深色模式反色控件）。
4. **屏幕边框收窄**：现有 `.bs-bt-screen` 为 `12px` 粗边框，白桃主题下建议收窄至 `8px` 配大圆角，更贴合"温润"定位。
5. **悬浮球全局状态映射（可选增强）**：球体颜色随全局最紧急需求变化（平静奶白 → 过线泛粉 → Critical 桃红搏动），玩家不展开面板也能感知"她现在状态不对"。实现仅需在 `renderMetabolismSummary` 计算全局 max state 并给球体加 `data-need-state` 属性，约 10 行 JS。
6. **多 Critical 传染抑制（可选增强）**：同屏超过 2 个 Critical 时，仅 overfill 比例最高者保持脉冲，其余降级为静态红框——所有格子都在呼吸时，呼吸就失去意义了。

### A.4 明确不做的事

- **液面 `transition` 动画**：`renderMetabolismSummary` 每次整体重建 innerHTML，DOM 节点销毁重建，transition 永远不会触发。要做需改渲染为补丁式更新，超出本任务范围，明确不做。
- **图标刻度轨**：fill 已归一化到 urge=100%，刻度信息量有限，不做。
- **格子整体浮动 / 文字抖动**：违反三层分离原则，不做。
