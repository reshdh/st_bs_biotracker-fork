## 问题

全仓库凡是用到入盆的地方都是 `getEngagedFetusCount(profile) > 0` 一个二值判断，
于是入盆变成了「一秒钟之内所有数值全换一套」。

真正的断点只有一个 —— **胎头越过骨盆入口平面那一下**。从那之后是逐渐下降、
压迫逐渐加重，直到抵到盆底。现在这个过程整个没有。

## 改成入盆深度 0→1

| 深度 | 对应 |
|---|---|
| 0 | 未入盆（高浮／可推回） |
| 0.3 | 刚越过入口平面（−3 站） |
| 0.6 | 坐骨棘水平（0 站） |
| 0.85 | 近盆底（+2 站） |
| 1.0 | 完全入盆、抵到盆底（+3 站，临产前一两天） |

## 两条口径

### 胎数决定有没有，深度决定压多重

多胎那条口径不变 —— 第二个胎头挤不进同一个骨盆入口，压的还是同一个膀胱，
所以「有没有入盆」对膀胱仍是二值的；**深度是那一个胎头下降到哪**。

便意那边不同：直肠被整个子宫下段的重量压，所以**胎数维度保留**（见 TASK-01 §6.1）。

### 便意地板挑 0.6 而不是 0.3

地板 22 的物理是「胎头顶着直肠前壁」。越过入口平面还顶不到直肠，
**到坐骨棘水平才真的贴上**。

尿意的线从 0.3 就开始压，因为膀胱在前、位置更高。

## 验证

1. **深度是连续的**：深度从 0 走到 1，尿意三条线、盆底系数、便意地板
   **中间不出台阶** —— 相邻 0.05 步长的差值单调且有界。这是本任务的核心断言。
2. **两端对齐现值**：深度 1.0 时所有数值等于现在二值判断为真时的值，
   深度 0 时等于现在为假时的值。**入盆后与未入盆的行为零变化**，改的只是中间那一段。
3. **深度要进序列化**：`METABOLISM_PATCH_KEYS` 只覆盖八个代谢键，深度是新持久状态。
4. **多胎回归**：双胎只有先露那一个入盆，深度跟着它走；膀胱侧仍是二值。
   两个同时入盆是交锁双胎（约 1/1000，要剖），几何上允许但不必特殊处理。
