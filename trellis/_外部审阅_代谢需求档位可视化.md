# 代谢需求的档位可视化（求方案）

## 这是什么

SillyTavern（酒馆）的生理状态追踪插件 BS BioTracker，用数值模拟角色从非孕到孕期到产后的代谢状态，服务于角色扮演叙事。面板是一个复古寻呼机造型的悬浮窗。

「代谢需求」是角色追踪页里的一格：五个图标格子并排，每格一个需求 —— 尿意 / 便意 / 饿意 / 困意 / 乳意（衍生种族多一个 flux）。

## 现在长什么样

每格只显示一个裸数字：

```
尿意 12    便意 8    饿意 30    困意 10    乳意 5
```

## 我们想解决什么

**这些需求的上限是弹性的，所以裸数字读不出状态。**

比如尿意的「该去了」那条线（urge）随孕周和入盆深度一直在动：非孕 100、孕晚期未入盆 60、入盆后 58。所以屏幕上一个孤零零的 `48`，看的人无法知道她是还早还是快憋不住了。

档位其实已经算好了（尿意六档：无/低/中/高/满/爆），但只写进了 `aria-label`，屏幕上不显示：

```
尿意  屏幕显示 12   aria 里藏着「尿意: 无 (12)」
便意  屏幕显示  8   aria 里藏着「便意: 0 (8)」
饿意  屏幕显示 30   aria 里藏着「饿意: 低 (30)」
```

**想要的是：肉眼一眼能看出现在在哪一档、离过线还有多远、过线了多少。想听听有什么方案。**

## 现状的几个事实（实测，不是估的）

| 项 | 实测值 |
|---|---|
| 格子尺寸 | 80 × 87 px |
| 图标容器 | 34 × 34 px |
| 格子内现有内容 | 三行：图标 / 标签（0.78em）/ 数值（0.82em） |
| 主题数 | 12 套，配色全部由 `--bsbt-lcd-text` 和 `--bsbt-lcd-bg` 派生 |
| 图标实现 | CSS `mask-image` 的单色形状（水滴、卷纸、鸡腿、月亮、奶瓶） |
| 档位数 | 尿意/饿意/困意/乳意 6 档；便意 6 段（段号 0–5，设计上没有中文档名）；体力 5 档 |

图标现在是三层，都从底部往上长：

```
bs-bt-need-icon-base       底纹，24% 不透明度的轮廓
bs-bt-need-icon-fill       填充层，高度 = --bs-bt-need-fill      = value / urge
bs-bt-need-icon-overfill   溢出层，高度 = --bs-bt-need-overfill  = (value − urge) / (cap − urge)
```

**溢出层目前实际上看不见**：`tone` 在 `value >= urge` 时变成 `high`，而 `high` 会把填充层的颜色覆盖成跟溢出层同一个红。活页面量到的 computed color 两层完全相同（`color(srgb 0.754039 0.258039 0.305569)`），所以「满」和「爆」现在看起来一样。

数据层不需要动：`value` / `urge` / `cap` / `level` 全都已经算好了（见 `normalizeMetabolismNeed` 的返回值），也有测试覆盖（445/445 绿）。**这是显示问题，不是数据问题。**

## 几条硬约束

- 格子尺寸和布局是既定的，方案要在 80 × 87 里成立。
- 不新增或重画图标资源，图标是现成的 SVG mask。
- 不引入第三方库，这是单文件 CSS ＋ 原生 JS 的插件。
- 不动数据层，只改显示。
- 目标是**肉眼直接看见**，所以 hover tooltip 不算解决（现在已经有 `aria-label` 了）。
- 12 套主题都要成立。现有做法是硬编码一个色相再 `color-mix` 混入主题文字色。
